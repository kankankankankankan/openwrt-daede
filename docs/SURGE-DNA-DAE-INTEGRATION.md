## 1. 用户目标与已确认方向

将修改后的 daede 插件编译进用户的 ImmortalWrt 固件。用户打开 LuCI 中的 daede，登录 Surge DNA 会员配置系统，获取适合 dae 的完整配置，保存并启用。会员配置系统网页同时提供 dae 配置下载。

已确认采用“服务端生成，插件获取并应用”：

1. Surge DNA 服务端负责会员认证、节点来源、规则适配和 dae 配置输出。
2. 路由器插件负责登录入口、同步、本机网络参数、校验、应用与恢复。
3. 保留现有 Surge 和 QuanX 功能。
4. 第一阶段建议使用 `luci-app-daede + dae`。daed 的独立面板、数据库和 GraphQL 配置链路另行适配，不应默认认为导入 dae 文件即可同步 daed。

第 4 项属于实施建议，尚未完成固件选择和实机验证。

## 3. 当前服务链路与可复用能力

### 3.1 已存在的接口

| 接口 | 当前行为 |
| --- | --- |
| `POST /api/login` | 接收 `username`、`password`、`turnstileToken`，调用会员系统；成功返回 `sessionId` 并设置 `sid` Cookie |
| `GET /api/state` | 根据会话返回用户资料、启用平台和所属任务 |
| `GET /api/captcha-config` | 获取登录验证码配置 |
| `POST /api/convert` | 为指定平台生成配置；当前平台为 `macos`、`ios`、`quanx` |
| `POST /api/refresh` | 按 `jobId` 刷新当前用户所属任务 |
| `POST /api/subscription-link` | 获取会员订阅来源 |
| `GET /api/surge/{jobId}/conf` | 输出托管配置 |
| `GET /api/surge/{jobId}/nodes` | 输出客户端对应的节点内容 |
| `GET /api/surge/{jobId}/rules.list` | 从 Surge 配置提取规则文本 |
| `POST /api/logout` | 删除会话并清除 Cookie |

当前 `requireSession` 从 Cookie 读取 `sid`，没有核实到可供插件直接使用的 Bearer 会话接口。插件若复用现有认证，需在路由器后端维护会话 Cookie。

当前下载入口按任务 ID 查找配置，没有要求浏览器登录会话。因此下载链接本身属于访问凭据，不能放进公开日志或固件。

### 3.2 可复用逻辑

- 会员登录、套餐信息和订阅来源发现。
- 同账户同平台复用任务，重新登录后重新关联任务。
- 订阅失效时的续链、其他可用会话尝试和历史快照回退。
- 定时刷新、远端模板缓存、本地模板回退。
- SQLite 存储及部分敏感字段加密。加密依赖密钥配置，并非全部字段自动加密。

### 3.3 外部依赖

登录调用 MMWX 官方安全客户端。缺少客户端时，代码直接返回服务不可用；原压缩包没有包含该客户端。实施前需核对生产环境的 `MMWX_TOKEN_CLIENT`、相关脚本路径和运行权限。

登录支持 Turnstile。如果上游开启验证码，需要设计在受支持网页完成验证或设备授权的流程。不能承诺所有环境都能仅输入账号密码完成登录，也不能绕过上游验证。

以下均为待实现设计。

### 4.1 dae 平台与任务

- 不把 LAN、WAN 网卡名称等设备差异固定进同账户共享任务。

### 4.2 节点输出

保留原始订阅或使用保留完整协议参数的中间结构，再输出目标 dae 支持的节点格式。当前 `parseProxies` 的结果围绕 Surge 字段组织，不能默认保证往返转换无损。

对实际订阅中的每类协议核对目标 dae 构建的支持情况，重点覆盖 TLS、SNI、证书验证、传输方式和协议专有参数。无法转换的节点要返回数量和原因；全部不可用时禁止发布新配置。

节点输出接口与整份配置的交付形式应在实施时固定：第一版优先以可验证的完整配置为交付单元；后续若拆分节点订阅，必须验证更新和离线回退行为。

### 4.3 规则与策略组

已统计本地 Surge 模板 `[Rule]`：64 条 `RULE-SET`、9 条 `DOMAIN-SUFFIX`、5 条 `DOMAIN`，以及各 1 条 `AND`、`IP-CIDR`、`GEOIP`、`FINAL`。

此统计只针对压缩包内备用模板，未抓取远端模板及规则集内容，不能代表生产规则总量。

| 规则或配置内容 | 处理要求 |
| --- | --- |
| 域名、域名后缀、关键词、IP 网段 | 按目标 dae 语法映射，保持匹配顺序 |
| 远程 `RULE-SET` | 服务端获取后解析、缓存和转换；原 Surge 规则集 URL 不直接作为 dae 路由规则使用 |
| `GEOIP` | 核对目标 geo 数据资源及最终配置引用 |
| `FINAL` | 明确 dae 默认出口与 DNS 失败场景的处理 |
| 策略组和地区筛选 | 建立稳定组标识，验证成员来源、组引用和选择行为 |
| 进程规则 | 区分路由器本机流量与 LAN 转发流量；不承诺能识别 LAN 设备的应用进程 |
| User-Agent、URL、Surge 专用动作 | 单独列出适配或不支持项，禁止静默丢弃 |
| 私人设备、SSID、网段和设备转发规则 | 从通用会员模板中分离，不能向所有用户默认下发 |
| DNS 设置 | 单独设计解析出口、防循环和启动所需解析，不能整段复制 Surge 设置 |

第一版先固定可支持的规则集合，输出明确的适配报告。对影响主要分流的未支持规则，阻止发布或要求先调整模板。

### 4.4 拟定接口契约

下表为设计草案，当前服务器未提供 dae 下载入口。

| 操作 | 拟定接口 | 要求 |
| --- | --- | --- |
| 登录与状态 | 复用 `/api/login`、`/api/state` | 路由器后端保管会话，前端仅显示必要资料 |
| 生成 dae | `POST /api/convert`，`platform: "dae"` | 返回该用户的 dae 任务及配置元信息 |
| 下载 | `GET /api/dae/{jobId}/config.dae` | 返回 dae 文本；定义可撤销的访问凭据 |
| 刷新 | 复用 `/api/refresh` | 校验任务归属，失败保留上一次成功产物 |

建议任务元信息包含：平台、格式版本、内容摘要、生成时间、节点数量、规则数量、快照是否过期、警告与下载地址。时间与摘要用于判断是否有更新，不能替代身份校验。

到期会员是否还能读取旧配置、下载凭据如何撤销、退出后自动同步是否继续，必须制定一致策略，并写入接口测试。

## 5. 插件改造明细

### 5.1 使用流程

首次打开：会员登录入口 → 获取配置 → 显示节点数量及必要提示 → 保存并启用。

已登录：会员状态、运行状态、上次同步时间、立即同步、重新登录。高级编辑折叠显示。

按钮需显示进行中、成功或失败原因，避免重复提交。同步失败时明确显示仍使用哪次成功配置。

### 5.2 路由器后端

- 新增受 LuCI 会话和最小权限 ACL 保护的登录、下载与应用操作。
- 请求走 HTTPS，校验证书，设置超时和体积限制。不能将密码拼进命令参数或日志。
- 不持久化会员密码；会话或下载凭据需受限保存，并纳入退出、备份和固件升级策略。
- 规则服务地址固定或严格限制，避免引入任意地址代理能力。
- 按本地网络配置适配接口参数，支持多网口和自定义桥；不得一律假设 `br-lan`。

### 5.3 云端配置模式

已确认风险：现有 UCI 表单保存会重新生成 `/etc/dae/config.dae`，可能覆盖云端内容。

新增明确的配置来源状态，例如本地与云端。云端模式下，普通本地表单不能覆盖托管配置；切换本地模式前保存快照并说明后续同步行为。下载路径、生成器路径和服务实际读取路径必须一致。

### 5.4 应用事务与恢复

1. 对同步加锁，避免手动操作与定时任务并发。
2. 下载到独立临时文件，检查 HTTP 状态、体积、内容类型和非空内容。
3. 适配本机参数，再用固件实际安装的 `dae validate` 校验最终配置。
4. 保存上一份成功配置和元信息，使用同文件系统原子替换。
5. 已运行时重载，首次启用时启动；确认进程、日志及基础连通性。
6. 应用失败恢复上一份文件并尝试恢复服务，报告恢复结果。
7. 成功后记录时间和摘要，清理临时文件并释放锁。

语法校验通过不等于代理可用，仍要验证 DNS、直连与代理出口。

## 8. 常见故障定位

| 现象 | 优先检查 | 恢复方式 |
| --- | --- | --- |
| 登录返回 503 | MMWX 客户端路径、文件和执行权限 | 修复服务器依赖 |
| 账号正确仍无法登录 | 上游响应、验证码与登录限流 | 完成验证或待限流恢复后重新登录 |
| 生成结果是 Surge | `normalizePlatform`、平台开关与转换分支 | 修正 dae 平台贯通逻辑 |
| 配置下载成功但无节点 | 上游订阅、解析结果、协议过滤 | 保留上次成功配置，修正节点输出 |
| 同步后又变回旧规则 | 本地表单生成器是否覆盖托管文件 | 修正云端模式保护和统一路径 |
| 校验成功但启动失败 | BTF、内核模块、接口、权限及服务日志 | 恢复旧配置，按运行错误处理 |
| 启动后 DNS 异常 | DNS 上游可达性、解析循环与出口规则 | 恢复旧配置并单独测试 DNS |
| 会员网页有配置，插件无任务 | 会话 Cookie、账户归属、平台过滤 | 重新登录并核对状态接口 |
| 更新失败仍显示最新 | 成功时间写入时机、快照标记 | 区分尝试时间和成功时间 |

日志应保留阶段、状态码、错误类别和耗时。密码、Cookie、JWT、完整私有下载地址和节点凭据必须隐藏。

这份备份可以作为 dae 规则模板基础。`config.dae` 已包含 AI、国内服务、Steam、开发工具、交易站点、广告、IPv4、IPv6 和 DNS 分流。它不能原样提交或直接作为公共模板，原因是其中包含真实订阅令牌、节点凭据、管理员密码、个人网段和本机接口。

审阅到的配置关系：

1. `config.dae` 使用手工配置，节点来自本地 `file://subscriptions/...` 文件。
2. UCI 中的机场订阅处于停用状态，且 UCI 的 LAN 接口与 `config.dae` 的接口不同，说明当前运行时以 `config.dae` 为准，UCI 记录存在历史残留。
3. `daed` UCI 显示启用，而 `daede` 选择 dae，后续应用前必须统一后端状态。
4. DNS 中包含内网地址，必须改为模板参数，不能向其他用户照搬。

后续处理方式：从 `config.dae` 提取规则、分组和 DNS 结构，替换真实节点与本机参数，增加唯一的 `__DAE_LAN_INTERFACE__` 占位符，再由服务端按会员节点生成。备份中的节点文件和 `wing.db` 只用于审阅和测试副本，不能进入仓库、固件或日志。
